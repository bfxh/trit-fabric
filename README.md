# trit-fabric — 三值状态机 AI（Fabric mod）

Minecraft **26.3** + Fabric Loader **0.20.1** 的客户端 mod。
把 AI 决策（Kleene K3 三值状态机）整个搬进游戏进程里跑，不再是外部程序按仿真按键。

适用整合包：`E:\MC\MC\profiles\26.3-Fabric 0.20.1 (1)`

## 和之前的方案有什么区别

| | 旧方案（Rust 外部进程 + 数据包） | 本方案（Fabric mod） |
|---|---|---|
| 感知 | 数据包写进计分板 → 日志 → 文本解析 | 直接读游戏世界，连续值、零延迟 |
| 操控 | `SendInput` 伪造物理按键，需要窗口焦点 | 直接写 `player.input` 和 `gameMode` |
| 崩溃残留 | 进程被杀会留下卡住的按下状态 | 没有外部进程，不存在这个问题 |
| 依赖 | 开机自启 + 计划任务 + 命名互斥量 | 跟着游戏启停，没有额外服务 |
| 精度 | 8 方向 × 3 档距离的量化 | 真实距离和角度 |

状态机逻辑本身（三值、投票、裁决、迟滞）两边**完全一致**，是从 `bfxh/trit-agent`
的 `fsm.rs` / `trit.rs` 逐条移植过来的，共用同一套单元测试。

## 维护说明（默认维护 mod，数据包不干）

本项目**默认只维护 Fabric mod 形态**。之前的「Rust 外部进程 + 数据包」形态**不再维护**
——它的决策精度、对游戏版本的强依赖、以及外部进程崩溃后残留的卡键问题，都比 mod 形态差，所以被取代。

- 想直接用：装 `build/out/trit-0.1.0.jar` + Fabric API 进 `mods/` 即可。
- 想自己搞数据包版：**欢迎，但有高手你搞吧** —— 仓库不再提供维护与支持，相关 PR 也大概率不会优先 review。
- 下面的玩法、模式、热键都指 mod 形态。

## 按键

| 键 | 作用 |
|---|---|
| **Y** | 打开「环盘菜单」选主动模式（巡逻 / 采集 / 战斗 / 建造 / 跟随 / 交还）；菜单内 **Y / 回车** 确认，**← →** 选择，退格取消，数字键 **1–6** 直达 |
| **F9** | 急停（立刻松手并交还控制权） |
| **F10** | 视角控制开关 |
| **F6** | 攻击开关 |
| **F7** | 移动开关 |

热键在游戏里的 `选项 → 控制 → TriT 状态机` 分类下可以改。

环盘菜单是 **HUD 叠层、不暂停游戏**：打开期间世界照常跑，你也能照常操作；选完模式关掉立刻生效。

接管后屏幕上方（物品栏之上）会显示一行状态，例如：

```
[TRIT] <for> 交战 engage |+0+000- | hp80% +威胁 d2.4 x1 | 有威胁
```

格式是 `模式 | 阶段 | 十个通道的方向 | 感知摘要 | 判定理由`（`<for>` 是当前模式代号）。

## 主动模式（环盘菜单）

按 **Y** 打开环盘菜单，选 AI「总体该干什么」。注意：模式和状态机的**瞬时阶段**（交战 / 撤退等）
是两回事 —— 无论什么模式，遇到威胁都会自动转入战斗 / 自保，模式只决定「没事干的时候主动去干嘛」。

| 模式 | 干啥 |
|---|---|
| 交还 (OFF) | 不主动做任何事，控制权全在你手里（但仍会在有威胁时自保） |
| 巡逻 (PATROL) | 到处走、遇墙绕、遇坑跳、卡住会自己解 |
| 采集 (FORAGE) | 主动找最近的树 / 矿走过去挖（只在这个模式主动挖，不和你抢控制权） |
| 战斗 (COMBAT) | 主动猎杀敌对生物；按距离用剑 / 斧近战或拉弓远程、绕圈不站桩、蹲下稳准 |
| 建造 (BUILD) | 前方是坑 / 液体就放方块搭桥 / 填坑（只在这个模式主动铺路） |
| 跟随 (FOLLOW) | 锚定在你身上跟着走 |

切换模式随时可以，不会打断当前正在做的事。

## 它会干什么（能力清单）

- **用武器**：近战自动选剑 / 斧；距离拉开且有弓 / 弩 + 箭就拉弓远程（蓄满松手），中间会蹲下稳住、站住不打断蓄力。
- **蹲下 / 隐藏**：有威胁但不在近战距离会蹲下降低存在感；站悬崖边蹲下防被推下去。
- **建造 / 填坑**：建造模式下前方是坑就放一格方块搭桥，别掉下去。
- **遮挡绕行**：采集 / 战斗目标被墙挡住视线时，不再傻站着硬挖硬射，而是接近或绕到能下手的角。
- **树挖完不卡**：每拍校验采集目标是否还在；挖掉了立刻失效并重扫，不会对着空气硬挖。
- **不干扰你操作（硬保证）**：只要你按了移动 / 攻击 / 使用键、正在破坏方块、或打开了任意原生界面
  （背包 / 聊天 / 任务栏…），AI 立刻全部让权，绝不抢控制权。
- **灵性**：没事干不会当木桩 —— 会转头扫视、低血且吃饱了会站桩回血、饿了会找吃的。

## 架构

```
com.bfxh.trit
├── core/        纯逻辑，不依赖 Minecraft
│   ├── Tri         K3 三值：未知参与运算时不猜
│   ├── Channel     10 个裁决通道（前后/左右/视角/俯仰/攻击/跳跃/使用/蹲下/远程/放置）
│   ├── Vote        行为模块投的票（方向 + 权重 + 是否按住）
│   ├── WorldView   感知快照，每个字段都允许「未知」
│   ├── Machine     阶段机 + 单通道裁决器（迟滞 + 弃权）
│   ├── Angles      朝向差计算
│   └── Mode        环盘菜单选出的主动模式（OFF/巡逻/采集/战斗/建造/跟随）
├── sense/Sensor    从游戏世界读感知（带性能预算和缓存；含玩家操作/遮挡/装备/地形检测）
├── act/
│   ├── AiInput     替换 player.input 的输入源
│   └── Actuator    把裁决写进游戏（武器切换/拉弓/放方块/蹲下…）
├── behave/         行为模块：巡逻 / 交战 / 撤退 / 避险 / 采集 / 进食 / 回血 / 静息扫视 / 隐藏 / 建造 / 锚点
├── TritMod         入口：注册热键 + 每拍驱动 + 跟踪原生界面
└── TritHud         HUD 叠层画环盘菜单（26.3 用 HudElement 抽取模型，不暂停游戏）
```

**26.3 适配要点**（和 1.20.x 的 Fabric mod 写法差异很大）：

- 菜单不用会暂停游戏的 `Screen`（26.3 的 Screen 渲染模型大改），改用 `HudElement`
  抽取模型 `extractRenderState(GuiGraphicsExtractor, DeltaTracker)` 画在 HUD 上，天然不暂停。
- 「你在开背包 / 聊天 / 任务栏」用 Fabric `ScreenEvents` 检测，检测到就立刻让权。
- 武器判定用 `ItemTags`（SWORDS / AXES）和 `BowItem` / `CrossbowItem`，因为 26.3 移除了
  `SwordItem` / `AxeItem` 这类物品子类。

一拍的流程：

```
感知 → peek 阶段 → 各模块独立投票 → 裁决 → 执行 → 显示状态
```

**「不猜」是硬约束**：裁决器里未知票的权重一旦压过已知票，这一拍就弃权（松手），
绝不把「不知道」当成「没有」。AI 撞墙、无视看不见的敌人，基本都是这条规则被破坏导致的。

## 构建

不用 Gradle —— 整个工程只依赖 MC 本体和 Fabric API，javac 直接编就够，
省掉 Gradle + Loom 几十分钟的下载和映射处理。

```bash
python build.py            # 编译 + 打包 + 装进整合包
python build.py --no-copy  # 只编译打包
python test.py             # 状态机内核自检（不需要 MC）
```

编译用的是游戏自带的 JDK 25（`meta/java_versions/mojang-java-runtime-epsilon`）。
**必须用 JDK 25**：MC 26.3 的 class 是 major 69，JDK 21 的 javac 读不了。
Fabric API 缺失时 `build.py` 会自己去 Modrinth 拉 26.3 的版本。

产出：`build/out/trit-0.1.0.jar`，直接扔进 `mods/`。
Fabric API 是硬依赖，脚本会一并放进 `mods/`。

## 自检

`python test.py` 跑 **76 项**（内核 59 + 行为仿真 17），覆盖：

- K3 真值表：`not` 对合、De Morgan、未知不被猜成「是」
- 朝向差的符号约定（搞反会导致朝反方向转）
- 状态机：停机、未知压制、迟滞防抖、通道禁用、低血撤退、死亡重生、未知威胁不交战
- 交手记录把「未知威胁」抬成「有威胁」
- `peek` 与 `step` 结果一致

行为仿真（`SimTest`）不进游戏，直接喂构造好的感知快照，检查典型场景下 AI 会做什么：
巡逻会走、看到树会走过去、贴着树会站住按住左键挖、4 格外的敌人只接近不出手、
2 格内会打且是脉冲不是按住、残血会退、墙前不顶、岩浆旁避险压过巡逻、饿了会吃。
这类测试专门防「票权和迟滞配错导致某个通道永远停在 0」—— 每一条票单独看都对，
但合起来 AI 就是站着不动，光读代码发现不了。

## 排查

启动过一次之后跑：

```bash
python diagnose.py
```

会列出 `mods/` 里每个 jar 的结构（有没有 `fabric.mod.json`、多少 class），
并从日志里挑出 trit / fabric / 报错相关的行。日志找不到会提示候选路径。
