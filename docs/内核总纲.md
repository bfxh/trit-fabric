## 0. 定位：内核是什么，不是什么

**一句话**：内核是一套**带证据治理的三值预测-承诺循环**（predict → commit → refine），
它对外只要求四件事，其余全是载体的事。

| 内核**是** | 内核**不是** |
|---|---|
| 值模型：K3 三值 + opt-in Belnap 四值，Unknown 是一等公民 | 某个游戏的 AI 类库 |
| 信念台账：每条知识带出处、证据级、适用域、反例计数、双时态 | 「模型权重 + 一堆 if-else」 |
| 前向模型库 + 技能包络：可辨识、可弃权、可跨游戏复用 | 运行时解析游戏描述的通用引擎 |
| 判据表：可离线做等价/SAT/BDD 验证的决策结构 | 手写常量散落各行为的黑箱 |
| 通道调度：同拍并发 + 优先级与资源互斥 | 串行脚本队列 |

**为什么要这么切**：上一版设计的失败模式是「mod 里长出一套认知，Rust 仓里长出另一套认知」，
两边共用词汇但不同用逻辑，于是每次改进都要写两遍、验证也验证不到内核上。
本总纲的判据是：**任何新的能力，先问它落在内核哪一件东西上；答不出来就不该做。**

**现在的真实程度**（先摊开，别当已完成）：
- 已落地并全绿：K3 三值 / 投票-裁决-迟滞 / 弹幕逐拍外推 + 每类在线学残差 / 摄像头预算闸门。
  离线 161 项断言 + 载体构建通过；**实机零验证**。
- 未落地（本文件其余部分都是设计）：四值台账、volley 成簇、ORCA 速度投影、包络辨识、
  并发调度、跨游戏载体。

## 1. 分层与四插槽契约

```
        ┌────────────────────────── K 内核（Rust）──────────────────────────┐
        │ Tri/B4 值 │ 信念台账 │ 前向模型库 │ 判据表(policy) │ 技能包络 │ 调度 │
        └───────▲───────────────────────────────────────────────▲──────────┘
                │ 观测（符号化，带未知）                        │ 通道向量（每通道 -1/0/+1）
        ┌───────┴───────────────────────────────────────────────┴──────────┐
        │               C 载体（每游戏一个，薄：解析输入、写按键）           │
        ├──────────────────────── G 描述（离线编译）─────────────────────────┤
        │   词汇表（对象类型/交互/终止）│ 物理表（重力/阻力/速度）│ 技能槽声明  │
        └───────────────────────────────────────────────────────────────────┘
```

**载体必须提供且只提供四个插槽**：

1. **词汇表**：对象类型、类型间交互、终止条件。骨架直接借 VGDL 的三分
   （SpriteSet / InteractionSet / TerminationSet）——它够用于 2D 网格类；
   3D/时机类覆盖不了的部分由载体的扩展词汇承担。
2. **观测抽取**：把游戏内存/像素变成对象中心的符号观测。
   代价有实测依据：对象抽取比视觉抽取快约两个量级（OCAtari 报 RAM 抽取比视觉抽取快 ~50×；
   MinAtar 单帧 0.03 ms / CPU），但**同一篇自曝若干游戏对象抽不全**（护盾、氧气条）——
   所以抽取器必须能报「我抽不到」，即 `Unknown`，这是 `[C]` 类问题（弱约束生态），
   不是三值或二进制的本质。
3. **物理表**：给内核的可辨识常数初值（重力、阻力、速度上限、体力代价）。
   **允许留空**：留空 = `Unknown`，内核靠 §5 的在线辨识补。
4. **执行器**：内核每拍输出一个**通道向量**（每通道 −1/0/+1 + 可选按住位），
   载体负责翻译成按键/点击。VPT 的教训值得抄：动作单位必须是「键位 + 按住时长 + 上下文」，
   因为同一个键在不同上下文语义不同（E 在 GUI 里是修饰键）。

**硬约束（可判红）**：K 层不许出现任何游戏名、方块名、实体名。
判据 = 对内核源码做一次符号级扫描，出现载体词汇即红。这是 `[C]` 类治理，不归类不算结论。

## 2. 内核的六件东西，对到已有 crate

只列**已经存在且公开接口可用**的（按各 crate 自述与实际 `pub` 项核对）：

| 内核构件 | 现成 crate | 实际能力（已核对） | 还缺什么 |
|---|---|---|---|
| 值模型 | `trit-core` | K3 / Ł3 / Bochvar 语义、AST、位并行表示（双导轨 ones/unknowns）、与二进制互操作 | 无 |
| 四值台账 | `trit-belnap` | `B4{T,F,B,N}` + `eval` + 真值表 `table/table_within` | 需要「证据集 + 双时态」的**存储层**（现只有逻辑） |
| 判据表 | `trit-policy` | `Policy` / `Assertion` / `Engine`，构建期定义展开 + 全赋值断言检查 | 把载体的票权/阈值搬进表；表→C/CSV 的导出走 `trit-build` |
| 等价与覆盖验证 | `trit-sat` / `trit-bdd` | dual-rail + SAT 符号化判定；三值等价 BDD canonical 判定 | 判据表改一版要能证「新旧只在预期格上不同」 |
| 可测性 | `trit-circuit` | AIGER/BLIF 读写、X 传播、**stuck-at 可测性（ATPG）** | 把行为链编成网表的编译器（见 §7） |
| 技能包络 | — | 内核侧无。最接近的是 `trit-net`（{-1,0,+1} 权重 + X 输入 + 确定/弃权解析、`Witness`/`Outcome`） | 全新：options + 参数辨识 + 可达性 |
| 并发调度 | `trit-schedule` | `Task`/`Dependency`/`ScheduleInput`/`ScheduledTask`/`DeferReason`/`DeferredTask` —— **三值依赖的静态 DAG 调度** | 每拍重算的时限版（现在像离线调度器） |
| 神经层算力 | `trit-ops` / `trit-dot` / `trit-gpu` | trit×f32 矩阵向量乘、位并行点积（XNOR+POPC）、GPU 对照 | 微神经元层用哪个精度档要有同字节预算的二进制基线（规则 6） |
| 伞包/工具 | `sansheng` / `trit-cli` / `trit-eval` / `trit-wasm` | 三值推理工具箱伞包；CLI 求值/真值表/等价/网表；**WASM 绑定已含 Belnap 求值与 ATPG** | 载体桥（见 §6 的 L2/L3 级） |

**结论 `[A]`**：三值在这里的红利是**表示层**的——`Unknown` 是原子值而不是 `(bool, err)`，
所以「抽取器不认识这个对象」「读不到重力常数」「这条知识被反证」这三种情况
不需要三种不同的补丁机制，全都落进同一个值模型。这一条是整个总纲的承重墙。
**红利不等于免费**：双导轨每 trit 占 2 bit 是 `[B]`（宿主平台的税），不许记成 A 的成绩。

## 3. 三值贯穿到哪里为止

用户口径已经是明确的：**学的东西走三值，连续量（几何、位姿、颜色）走浮点**。
本总纲把它写成可检查的边界：

| 层 | 取值 | 理由 |
|---|---|---|
| 裁决 / 票 / 阶段 / 判据 | K3 三值 | 弃权是安全属性，不是缺失值 |
| 知识的证据状态 | Belnap 四值 | §4 详述：必须能同时「有真证据」和「有假证据」 |
| 弹道坐标、速度、CPA/TTI、包络参数 | f32/f64 | 连续量；量化会直接毁掉物理 |
| 微神经元的**权重** | {-1,0,+1} trit（`trit-net` 口径） | 权重三值化后才谈得上「无乘法点积」与可验证 |
| 微神经元的**输入** | 几何量走 f32，经阈值/分位转成三值再入网 | 转的那一步就是判据，必须进 policy 表可验 |

**新增的一条设计判断（上一版没有）**：**辨识本身也带三态**。
包络参数 v0、g 的估计要么给「可信区间」，要么给 `Unknown`；
不允许在残差门控没过的时候拿一个拟合值当事实用 —— 这正是 `trit-unsafe` 审 unsafe 的同一套
`Safe / Unknown / Risky` 口径，可以直接复用它的判定形态。

## 4. 知识治理：「错的也要知道」需要四值，不是三值

这是用户提得最狠的一条，也是数学上最容易被做错的：**三值表达不了「我曾以为真、现在被推翻」**，
因为 `Unknown` 只表示「无证据」，不表示「有反证据」。

文献给的口径很硬：

- Belnap 1977 的 FOUR：真值 = (真证据集, 假证据集) 双分量，知识格与真值格分离，
  允许多值态 `B`（两边都有证据）；Priest 1979 LP 保证局部矛盾不爆炸。
- Gelfond & Lifschitz 1988：**经典否定与默认否定必须两个符号**——这正是「为假 vs 未知」的最小形式化。
- Reiter 1978 / Clark 1978 的 CWA 与「推不出即当假」**是本项目明令禁止的语义**。
- Imielinski & Lipski 1984：NULL 的通用语义**无法完备**——所以别指望用 null 表达这件事。
- Fagin/Halpern/Moses/Vardi 1995：「知道自己错」必须是**显式字段**，不能指望从推导里涌现。

### 4.1 台账条目（内核一等对象）

```
Knowledge {
  claim        : Expr        // K3/B4 公式，可进 policy 表
  provenance   : {source, obtained_at}          // why-溯源（Green 2007 半环口径）
  domain       : 适用域谓词                       // 域外使用 = 另一类错误，见 4.3
  evidence     : (T_set, F_set)                  // Belnap 双证据集
  grade        : Proved / Undetermined / Refuted  // 沿用三值审计定式
  counterex    : 可执行反例断言（CEGAR 的「反例」） // 谓词触发即我错
  valid_time / transaction_time                   // 双时态（Snodgrass 1992）
  drift        : 累计误差计数器（ADWIN / Page-Hinkley）
  expiry       : 到期拍（设计形问题必须带 ≤N 拍到期）
}
```

`grade` 三档 + 「`F_set` 非空」的组合，才是用户要的四种状态：
**已知为真 / 未知 / 已知为假 / 曾以为真后被证伪**。第四种必须可查（双时态 + `F_set`），
否则「错误的知识」在系统里长得跟「没有知识」一样。

### 4.2 撤回必须是 O(1)

- JTMS（Doyle 1979）记理由并**级联撤回**，代价大；ATMS（de Kleer 1986）不撤回，
  改为给每条结论挂「成立所需假设集」标签。
- 复杂度不是可以努力克服的那种：命题知识库的 revision/update/contraction 判定
  多为 **Σ₂ᵖ-完全**（Eiter & Gottlob 1992），ATMS/JTMS 的信念计算同阶（Rutenburg 1994）；
  一阶「是否被证伪」根本不可判定（Church 1936）。
- ⇒ 单拍微秒级预算下的唯一可行解：**有界依赖图 + 标签翻转**。
  翻案 = 给该条目的 `F_set` 加一项、把 `grade` 改 `Refuted`、把依赖它的结论的标签重算——
  不遍历删除，不跑推理机。这是 `[D]`（与进制无关的复杂度），不许记到任何一边的账上。

### 4.3 两类错误要分开记账

| 错误类型 | 是什么 | 检测手段 | 后果 |
|---|---|---|---|
| **知识本身错** | 学出来的规律不成立 | 反例断言触发（Popper 1934：∀ 命题可判伪不可判真） | 直接 `Refuted` |
| **域外误用** | 知识在 A 域成立、被拿到 B 域用 | `domain` 谓词不满足 | 降 `Undetermined`（**不许**标 Refuted） |
| 已过期 | 世界变了（游戏版本/服务器规则） | ADWIN 越界、Page-Hinkley；revision 与 update 是两条码路（Katsuno & Mendelzon 1991） | 标 expired，留档可查 |
| 被污染 | 来源本身不可靠 | 标签投毒（Biggio 2012）、错标反推（Northcutt 2021 置信学习） | `provenance.reliability` 降权 |

「域外误用被标成 Refuted」是把好东西扔掉的典型错误；这一条要有测试。

### 4.4 从「猜的带」到「有保证的带」

现在的波动带是启发式（`0.35 + 1.8·(σ√t + |bias|t)`，封顶 3 格）。可升级：

- 共形预测：有限样本、分布无关覆盖率（Vovk 2005；Lei 等 2018）。
- **非平稳下在线只调一个 α**：自适应共形推断 ACI（Gibbs & Candès 2021）——最贴零训练预算。
- 可推广形式：共形风险控制（Bates 2021 RCPS；Angelopoulos & Bates 2023/2024 CRC），
  含义是**「误红率可以预算化」**——这比「更准」有用，因为它给了可以写进门限的数字。
- aleatoric 不可消、epistemic 随数据消失（Der Kiureghian & Ditlevsen 2009）⇒ 两者分开记账。
- 诚实边界：ADWIN/ACI 都需要 i.i.d. 或有界变化假设，**对抗性任意漂移可以骗过任何检测器**。
  所以目标写成「可预算的红错率」，不写「绝对正确」。

## 5. 三个子系统

### 5.1 弹幕：成簇、速度空间、别等算完才走

现状（载体侧已实现）：逐颗外推 → CPA/TTI → 每类学残差 → 波动带判据 → 5 候选各重跑外推取余量最大。
三个已知问题与对应技术：

1. **逐颗独立评估会低估夹击、高估走廊。** 齐射的耦合本质是**到达时间相关 + 同源误差**。
   - 火力分配与协同齐射有成熟抽象：TOT（同时到达）协同攻击（Zeng 等 2020）、
     weapon-target allocation（Aerospace 2018）。
   - 落地：先按 (owner, 发射时序, 方向扇区, 同源 bias/σ) **成簇**，簇是一等对象，
     带自己的 TTI 对齐度；躲避打分看「簇的最坏到达」而不是逐颗。
   - 编排识别可借 squad 层抽象：F.E.A.R. 的 GOAP + squad manager 按群层分派压制/包抄（Orkin 2006）、
     GDC 2017/2019 的群协调与 L4D Director 的压力预算 —— **识别单位是 volley/扇区/时序模板，不是单弹**。
2. **多威胁规避不该逐个重跑外推。** 速度空间里有直接工具：
   velocity obstacle（Fiorini & Shiller 1998）、collision cone、RVO（2008）/ORCA（2011）——
   多威胁是各 VO 在速度空间的**并集**，一次线性规划投影即得安全速度；
   要概率化有 PRVO（2017）与机会约束 MPC（Zhu 2019）。
   失败模式也有名有姓：**RVO 类方法会左右震荡**，HRVO（T-RO 2015）就是为 oscillation-free 设计的。
   这条替换掉我现在的「5 候选重跑」，且仍属微秒级（一个低维 LP）。
   最坏情况耦合另有 HJ 可达性 min-max 框架（Johnson & Tomlin 综述），但它受维数灾难，
   要靠分解（Herbert）才用得起来 —— **列为研究项，不进近期里程碑**。
3. **别等算好之后才走。** 这是 anytime 的本行：
   - Dean & Boddy 1988：规划耗时本身损效用，按剩余时间分级细化，先出可行粗解。
   - Zilberstein & Russell 1993 / Zilberstein 1996：传感-规划-行动同在一个 anytime 框架里，
     **「何时停算」本身就是可解的最优停止问题**；contract algorithm（IJCAI 1995）给「按预算买断」。
   - 带界的做法：ARA*（NeurIPS 2003）、Anytime D*（2005）、ANA*（2011）——
     每个解显式带 ε 次优界并随时间收紧。⇒ 承诺闸门写成：
     **当前保守解的 ε 界 ≤ 剩余 TTI 的容忍损失 ⇒ 立刻承诺动作，继续算只用于细化。**
   - 人类基线佐证：拦截任务里人不解完整弹道，用零化光学加速度/常数方位角边跑边更新
     （Lee 的 tau-OAC；Rozendaal 2003；Zhao 2015）。⇒ 「先起势再落点」不是偷懒，是更优的结构。
   - 防抖三件套（不然会变成来回横跳）：**平均驻留时间**（Morse 1999；Liberzon 2005）+
     双阈值迟滞（已有）+ **承诺代价**；并把上一拍方向作为先验保时序一致。
4. **类型是模态，不是硬判。** IMM（Blom & Bar-Shalom 1988）多模型软混合 + 马尔可夫转移，
   抗突变、优于硬判决；Lainiotis 1971 分区滤波；变点检测 BOCD（Adams & MacKay 2007）。
   ⇒ 弹的类型 = 离散模态，每模态带自己的 (g, drag) 与 σ，输出**混合后验**——
   现在这套「按 instanceof 硬判类 + 事后学修正」是它的退化特例。
5. **未证**：把上述规避理论直接用于弹幕游戏的公开实证，没找到
   （只有 IEEE-COG 2021 的东方像素基准，不涉规避建模）。所以这套是**借结构**，不是借结论。

### 5.2 动作与并发：跳怎么才算「会跳」

用户要的是四件事：会判断该不该跳、知道怎么跳/跳多高跳多远、能一边跳一边脚下放方块、
并且承认「有些游戏跳着更快」。分别有对应物：

- **技能表示**：options（Sutton/Precup/Singh 1999）的 initiation/termination 集合。
  `JUMP` 的 init = 上一拍 `on_ground`；term = 接地 **或撞顶**（撞顶是正常收尾，不是报错）。
  参数化：DMP（Ijspeert 2013；Saveriano 2023 综述）把幅度 × 时间两个标量作为缩放 ——
  **跳高与跳远是同一原语的两组标量**，这正好对上通道阈值，而不是写两套代码。
- **包络在线辨识（O(1)/拍）**：预测误差法（Ljung 1999）+ 带遗忘因子的 RLS（Vahidi 2004），
  以 `z = [1, t, t²]` 三参数回归即可逐拍出 v0 / g / 滞空 / 射程 —— 微秒级，符合硬预算。
  ⚠️ 教科书式「滞空法 h = gT²/8」在真实跳里被证有系统偏差（Gonçalves 2024；Eythorsdottir 2024）
  ⇒ 只信「平地、无碰撞」的标定拍，其余按残差门控降为 `Undetermined`。
  ⇒ 可达性判据：`(Δx, Δy) ∈ envelope(v0, g)`；跨坑/台阶的连接语义借 off-mesh link 的显式声明
  （Recast / Unity NavMeshLink），**不要靠自由落体模拟去猜**。
- **跳的价值**（要可算，不是感觉）：
  - Source 引擎的 bunny-hop：空中加速无摩擦上限、**落地当拍再跳才能保速** ⇒
    「跳 > 走」是可量化收益，收益 = 同拍 `jump ∧ on_ground` 带来的速度保持。
  - Minecraft 口径（维基，实机再校）：跳高约 1.2522 格、平地滞空约 12 tick、起跳要求上一拍着地；
    疾跑 5.612 vs 行走 4.317 m/s，连跳略快但饥饿代价约 4× ⇒
    **价值 = 速度收益 − 体力代价 − 失败代价**，三项都必须可测，缺一项就 `Unknown` 不跳。
  - 「高地看得更清楚」：**未证** —— 没有找到量化 FPS 高地优势的论文，只有定性 level-design 资料。
    ⇒ 不许写成「已知有利」，只能由 §5.3 的信息增益打分**当场算出来**。
- **并发（这是内核侧的新构件，不是载体的技巧）**：
  - 「同拍多通道为真」的正确抽象是 **GraphPlan 的同层**（Blum & Furst 1995）：
    同一层里只允许互不冲突的动作并发 ⇒ 立柱跳 = `JUMP` 与 `PLACE(下)` 在同一层，
    因为它们的资源集不相交（一个占腿，一个占主手 + 目标格）。
  - 行为树的教训很具体：**BT 的并行节点有隐性竞态**（Colledanchise & Natale 2018/2021）
    ⇒ 竞态只应落在共享资源上，做 **per-resource 互斥锁**（手、方块槽、目标格）；
    不要做「通道级全局互斥」。（用户提到的「Coloured BT 2022」原始出处未检到，标**未证**，
    依据用综述 Iovino 2022。）
  - 抢占与不反转：RMS 可调度性（Liu & Layland 1973，利用率 < ln2）+ 优先级继承
    （Sha & Rajkovic 1990）⇒ 保命的跳可以**抢占**放置锁且不发生优先级反转。
    现成的 `trit-schedule`（三值依赖静态 DAG，带 `DeferReason`）就是这个的位置——
    缺的是「每拍重算 + 硬时限」版本。
  - 与三值同构的旁证：subsumption 的抑制/接管（Brooks 1986；Connell 1987 已用于虚拟生物）
    **就是通道级否决**，与我现在的多模块投票同形 ⇒ 不需要新机制，需要的是把「谁抑制谁」写进 policy 表可验。
  - GOAP（Orkin 2006）与 HTN（Ontañón & Buro 2014）偏串行分解
    ⇒ 规划层**最终必须吐通道向量**，不能吐「动作序列」了事。
- **⚠️ 反作弊是真的失效路径**（上一版设计完全没考虑）：Grim 做**精确移动模拟**校验，
  Paper 有 `moved-too-quickly-multiplier`；版本更迭就会造出生产假阳（Grim issue #1911）。
  ⇒ 内核必须维护**两套包络**：`envelope_local`（我能跳多高）与 `envelope_server`（服端允许什么），
  **取交集才行动，超出即弃权**；并把「被服端判违规」作为一种**反证**记进 §4 台账（它属于
  「域外误用 / 已过期」而不是「知识本身错」）。

### 5.3 主动感知：为了看清而移动，要能用同一把尺比

- frontier-based exploration（Yamauchi 1999）；next-best-view（Kriegel 2011 用表面补全选点，
  选点极快；Alsadik 2025 综述）；期望自由能的探索项 = 期望信息增益（Da Costa & Parr 2020）。
- 微秒级可算的极简形式：
  `score = 新增未知格数 × 有效视距 − 拍成本`。
  **转头便宜、跳贵、换机位更贵**——三项都进同一个效用函数才可比分，
  「跳不跳」和「调不调镜头」于是变成同一个决策的两个解，而不是两套规则。
- 与 §4 咬合：`score` 里的「未知格数」直接来自台账的 `Undetermined` 面积，
  所以知识治理不是道德条款，它有数值出口。

## 6. 跨游戏泛化：迁移结构，不迁移数值

- **有实证的部分**：迁移**自动发现的 afterstate / 块**（AbCRL，Banerjee 2007）
  与迁移**按对象类型的前向模型**（Object-Model Transfer，Braylan 等 2016，在 30 个 VGDL 游戏上）
  都提高了样本效率；而**迁移数值权重跨游戏没有正面证据**——
  2022 年 GVGAI 学习赛道冠军 DORL 明说跨游戏迁移是未来工作，实际靠每游戏基模型 + 元选择。
  ⇒ 内核迁移的是：**判据结构（policy 表骨架）、簇/模态抽象、技能包络的形状**；
  数值（v0、g、体力代价、阈值）**每游戏重辨识**，不做拷贝。
- **描述只在离线用**。这是最贵的一课：Ludii 组实测**纯逻辑解译比组件式实现慢 2–40×，
  国际象棋 >200×（0.06 playout/s）**。⇒ 游戏描述/规则在**离线编译**成每游戏的前向模型与查表，
  **运行时绝不解析描述**。这条直接决定「能玩所有游戏」是**可扩展**而不是**免费**。
- **动作合法性掩码**：Ye 等 2021 证明非法动作掩码等价于状态相关的策略梯度，
  且合法集越大越关键 ⇒ 载体的四插槽里「当前合法通道集」是必填项，内核在掩码外一律弃权。
- **抽象太粗会被打脸**：O-MCTS（de Waard 2016）量化过——小关卡里粗选项赢，
  大关卡因选项过粗输。⇒ 技能必须可**递归分解**（options 套 options），不是一层拍平。
- **游戏无关性的天花板**（别自欺）：GVGAI 历届冠军**平均只赢约 50% 的局**；
  DRL 在 8 个游戏里有 6 个打不过规划器；官方承认观测未必覆盖全状态，
  连续物理/时机类/3D/部分可观测被列为 future work。
  另有一条对本项目格外重要：GGP 侧结论「重启发式偏置在足够多游戏上不利」（Świechowski & Mandziuk 2015）
  ——而「投票→裁决→迟滞」正属于**幸存的那一类**（它是元层级控制，不是领域启发式）。
- **载体分级（按内核到游戏的距离，明确排期用）**：
  - `L0` 进程内直连（现在的 Minecraft 载体；内核逻辑嵌在宿主语言里）
  - `L1` FFI/静态库（Rust 内核 + C ABI，宿主同进程）
  - `L2` WASM（`trit-wasm` 已有求值/真值表/等价/Belnap/ATPG 的 JS 绑定 ⇒ 浏览器类载体今天就有入口）
  - `L3` 离线评测床（VGDL/GVGAI、MinAtar、ALE）——**这是内核的门，不是产品**
  排期纪律：内核的新能力**先过 L3 的判据，再进 L0/L1**。顺序反过来就又变成「两边各写一遍」。

## 7. 内核能给、而游戏侧给不出的东西

这是「为什么要搞内核」最硬的答案。三条我现在的载体写法根本做不到的检查：

1. **stuck-at 分析抓「永远为 0 的通道」**。
   我在载体侧反复踩过同一类 bug：每条票单独看都对，合起来某个通道永远不动，表现是「AI 站桩」。
   这在网表侧有学名 —— **stuck-at 可测性**，而 `trit-circuit` 已经实现了 X 传播与 ATPG
   （AIGER/BLIF 读写都在）。⇒ 把「行为 → 票 → 通道」编成三值网表，
   离线跑 ATPG 找**不可达/恒 0 的通道**，每次改编排自动判红。这是 `[D]`，任何进制都要付，
   但只有网表化工具才付得起。
2. **判据表的可验证性**。裁决逻辑（阈值、迟滞、弃权、抑制关系）搬进 `trit-policy`
   的 `Policy`/`Assertion`（构建期定义展开 + 全赋值断言检查），
   再用 `trit-bdd`（canonical 三值等价）/`trit-sat`（dual-rail + SAT）证明
   「改版前后只在预期的那些赋值格上不同」——这就是双向红的来源，
   比现在的「跑 161 个断言」强一个量级（断言只覆盖我想到要测的格）。
3. **三值审计定式的复用**。`trit-unsafe` 已经在用 `Safe / Unknown / Risky` 逐点判定再按 crate 合成，
   `trit-redteam` 只打自家产物 ——同一套形状直接搬到「阈值类判据」的 ±ε 网格扫描
   （Proved / Undetermined / Refuted），不用另造一套。

## 8. 度量与门（每条主张都要能判红）

规则：**没配判据的主张不算主张**。基线口径按 `trit` 的规则 6：任何对比必须同时给二进制基线，
并写明省的是带宽/存储还是指令数。

| 主张 | 判据（可自动红） | 现状 |
|---|---|---|
| Unknown 是一等公民 | 「没扫描」必须产出 ZERO/`Undetermined`，不许当 NEG；反例：注入未扫描拍，若判成「没有威胁」即红 | 载体侧有测试，内核侧未表化 |
| 四值台账 | 同一条知识可同时有真/假证据 ⇒ 必须落 `B` 而非塌成任一单值；且「曾以为真后被证伪」可查询 | 未做 |
| 撤回是 O(1) | 台账规模 N×10 时，单次翻案的墙钟增长 < log 级；超预算即红 | 未做 |
| 弹幕成簇 | 齐射（TOT 对齐）场景下，簇模型给出的最坏到达时间 ≤ 逐颗独立模型；且走廊被低估的情况出现即红 | 未做 |
| 别等算完才走 | 承诺拍 ≤ TTI 的 30%，且 ε 界随计算单调收紧；违反即红 | 未做 |
| 包络辨识 | 平地标定拍上 v0/g 的相对误差 < 5%；非标定拍必须降 `Undetermined` | 未做 |
| 并发立柱跳 | 同一拍 `JUMP ∧ PLACE` 同时生效且无资源竞态；连续 100 拍立柱上升 ≥ 阈值 | 未做 |
| 服端包络 | 超 `envelope_server` 的组合**必须弃权**；故意投一个违规组合，若执行即红 | 未做 |
| 内核不绑游戏 | 内核源码扫描出现载体词汇即红 | 未做 |
| 描述不运行时解析 | 载体初始化后单次决策耗时不含解析项；出现解析开销即红 | 未做 |

**未证清单（不许当依据用，只许当线索）**：高地优势的量化收益；把 VO/ORCA 直接用于弹幕规避的公开实证；
「Coloured BT」原始出处；零 LLM 的技能自动验收方法；GVGAI-MC / MAGE / PLAGE 的原始论文；
「通用不确定性不可能性」那类强否定结论（未逐字核验）。

## 10. 已知风险（写下来，别等出事）

1. **泛化 vs 零成本是真冲突**：Ludii 的 2–40× 就是这笔账的价码。我的解法是「离线编译描述」，
   但它把复杂度推给了**编译器和每游戏抽取表**——抽取表漏对象就是静默降级，
   必须靠「抽取器能报 Unknown」兜，否则表现为「看不见 = 没有」。
2. **微秒级预算下共形带可能算不起**：ACI 只调一个 α 是便宜的，但每拍的保序分位估计不免费；
   若退化成分位查表，覆盖保证就只剩「近似」——要实测，不许照抄文献声称。
3. **知识污染的自我强化**：错知识会喂出错的域判断（`domain` 谓词本身是学出来的）。
   对策是域谓词也要有反例断言和到期，但这是无限回归——**只在有界层数内治理，超出层数一律降 Unknown**。
4. **反作弊不可完全避免**：Grim 版本一动，包络就可能被判违规。弃权可以保命，但会掉表现；
   这条要写进载体的「已知缺点」而不是藏起来。
5. **实机仍未验证**：本总纲与现实现的全部证据都来自离线断言与静态构建。
   真机手感、帧时间、以及「躲得掉/跳得起/镜头没被抢」这三件事，**目前一条读数都没有**。
